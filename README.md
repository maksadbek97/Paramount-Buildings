# Paramount Buildings

Информационная система строительной компании (Django, интерфейс на русском).

## Как устроена работа

Всё строится вокруг объекта: взяли объект у генподрядчика → создали его в системе → всё остальное ведётся внутри него.

- **Главная** (ТЗ модуля «Главная / Dashboard») — фильтры периода и объекта, KPI (активные объекты, сумма договоров,
  поступления, расходы, денежный результат, дебиторка, кредиторка, просроченные задачи), блоки «Объекты», «Финансы»
  с графиком, «Работы», «Закупки», «Материалы», «Документы», «Задачи» (выполнить / перенести срок), «Последние
  операции», «Быстрые действия». Каждая цифра ведёт в свой раздел с фильтром. Поиск и уведомления — в верхней панели.
- **Мои объекты** — плитки с фото и статусом, завершённые на отдельной вкладке.
- **Объект** — вкладки: Обзор, Объёмы работ, Рабочие, Выработка, Материалы, Деньги, Замечания, Отчёты, Документы.
  Счётчики на вкладках показывают, где что-то ждёт действия.
- **Формы внутри объекта** (`/objects/<id>/new/<что>/`) — объект подставлен сам, в списках только его объёмы и
  исполнители, после сохранения возврат во вкладку объекта.
- **Верхняя панель** — логотип, рядом выбор объекта («Все объекты» или конкретный объект), уведомления,
  пользователь (Профиль, Выйти). Выбор запоминается в браузере и сохраняется при переходах: Главная
  и обзор «Документов» показывают данные выбранного объекта, списки документов сразу фильтруются по нему,
  в остальных разделах пункт ведёт в карточку объекта.
  На телефоне — нижняя панель с кнопкой «+».

- **Документы** (ТЗ модуля «Документы / Документооборот») — обзор со сроками и быстрыми действиями, единый реестр
  с фильтрами, поиском, сортировкой, настройкой колонок и экспортом, приказы (без кадровых), письма входящие /
  исходящие / внутренние, договоры с оплатами и сроками, поручения, номенклатура дел, журналы регистрации
  с атомарной нумерацией, шаблоны и фирменные бланки, подпись и печать с журналом использования, архив.
  Карточка документа: этапы, реквизиты, файлы и версии, согласование и подпись, исполнение, связи, история.
  Генератор писем на фирменном бланке: 7 шагов, обязательный вопрос о подписи и печати, готовый PDF
  с номером по журналу исходящих. Документ объекта виден во вкладке «Документы» объекта.
  Фирменные бланки компании (`docflow/blanks/`: письмо и приказ, DOCX) лежат в «Шаблонах» — их можно открыть
  и скачать. Письмо из генератора и новый приказ собираются на бланке сразу в двух видах: PDF и DOCX для Word.
  Предпросмотр, «Скачать PDF» и «Скачать Word» показывают именно тот документ, что заполнен: письмо — на бланке
  письма, приказ — на бланке приказа (`static/blank.js` собирает их в браузере, поэтому это работает и в демо).
  Весь текст документов — Arial 12 pt (на сервере без Arial берётся Liberation Sans с теми же размерами букв).

- **Финансы** (по шаблону компании «Фин план до 2026 года») — таблица как в Excel: вкладки «Сводная», лист каждого
  объекта, «Долги компании», «Движение денег». В каждой ячейке можно писать сразу: план, даты, факт, примечание;
  итоги блоков, «ИТОГО РАСХОДЫ», «ОСТАТОК» и сводная пересчитываются на месте, каждая правка сразу сохраняется
  (на сервере — в базу с записью в журнал, на сайте по ссылке — в браузере). Факт больше плана подсвечивается и
  попадает в уведомления. У объекта — договоры и доп. договоры, АВР. «Доход / Расход» — объект → категория → сумма
  в одном окне (на телефоне — круглая кнопка). «Скачать Excel» собирает файл по шаблону компании: те же листы,
  стили и формулы. Финансы объекта показаны и во вкладке «Финансы» карточки объекта.

## Модули

Система развивается по техническому заданию SMART BUILDING (ТОО «PARAMOUNT BUILDINGS», Казахстан, суммы в тенге).

- **Субподряд (главное)**: объёмы работ, взятые у генподрядчика (вид работ, объём, единица, цена, срок),
  бригады и рабочие на объёме, оплата им за объём или за день, выработка по дням,
  платежи (от генподрядчика, рабочим, материалы), остаток объёма, долги и прибыль.
- **Объекты**: код, город Казахстана, заказчик и генподрядчик, договор, сумма договора и бюджет,
  руководитель проекта, прораб, ПТО, 8 статусов (от «Планируется» до «Архив»), история операций.
- **ПТО и приёмка объёмов**: секции и этажи, прораб вносит выработку, ПТО принимает всё, часть или отклоняет.
  В учёт и в оплату идёт только принятый объём. Объём сверх плана — только с правом `allow_over_plan`,
  приёмка — с правом `review_worklog`. План-факт по всем видам работ.
- **Нормативы материалов**: расход на единицу работ, потребность на принятый объём, списание, перерасход.
- **Журнал действий**: кто, когда, что изменил (было → стало), причина изменения.
- **Обходы и замечания**: номер ЗМ-ГГГГ-00001, место (секция, этаж, помещение), фото, приоритет, срок.
  Замечание сразу создаёт задачу прорабу; дальше «в работе» → «на проверке» (фото выполнения) →
  «принято» или «возвращено на доработку» (право `review_remark`). Повторные замечания на том же месте видны сразу.
- **Задачи**: Новая → Принята → В работе → На проверке → Выполнена; ответственный обязателен,
  просрочка подсвечивается, подтвердить выполнение может только руководитель (право `close_task`).
- **Ежедневный отчёт прораба**: погода, люди, бригады, работы, материалы, техника, проблемы, план на завтра, фото;
  выработка и расход со склада за день подтягиваются сами; прораб подтверждает отчёт.
- **Предупреждения на главной**: дефицит, перерасход норм, риск задержки, превышение бюджета, просрочки.
- **Сотрудники и задачи**: должности, сотрудники, задачи с исполнителями и приоритетами.
- **Склад и материалы**: материалы, поставщики, приход и расход, остатки, предупреждение о низком остатке.
- **Финансы и сметы**: сметы с позициями, доходы и расходы, баланс по объекту и в целом.

## Запуск

```bash
pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

- Система: http://127.0.0.1:8000/ (вход по логину)
- Все данные вводятся прямо в интерфейсе (кнопки «+» на каждой странице, на телефоне — круглая кнопка внизу).
- Админ-панель для редких настроек: http://127.0.0.1:8000/admin/

https://maksadbek97.github.io/Paramount-Buildings/app/

```bash
python manage.py migrate
python manage.py seed_demo        # примерные данные
python manage.py build_static     # HTML в папку _site/app
```

## Структура

| Папка | Назначение |
|---|---|
| `config/` | настройки проекта |
| `core/` | главная страница и представления |
| `contracts/` | субподряд: объёмы, бригады, выработка, платежи |

## Как считаются деньги по объёму

- **Сумма договора** = объём × цена за единицу (сколько нам заплатит генподрядчик за всё).
- **Начислено рабочим**: при оплате за объём — сделанный ими объём × их ставка;
  при оплате за день — число человеко-дней × ставка за день.
- **Остаток** = План − Принято; **Выполнение %** = Принято ÷ План × 100; **Стоимость работ** = Принято × Цена.
- **Прибыль** = стоимость принятых работ − начислено рабочим − материалы − прочие расходы.
- **На руках** = получено от генподрядчика − выплачено рабочим − материалы − прочее.

База данных по умолчанию SQLite (`db.sqlite3`, в репозиторий не попадает).
